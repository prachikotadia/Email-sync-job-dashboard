# Mac Setup Guide

This project is fully compatible with macOS. Follow these steps to get started.

## Prerequisites

1. **Docker Desktop for Mac** - Download from [docker.com](https://www.docker.com/products/docker-desktop/)
2. **Git** - Usually pre-installed, or install via Xcode Command Line Tools: `xcode-select --install`

## Quick Start

### 1. Clone the Repository

```bash
git clone <repository-url>
cd Email-sync-job-dashboard
```

### 2. Run Setup Script

```bash
chmod +x setup.sh
./setup.sh
```

This will:
- Check for Docker installation
- Create `.env` file from `.env.example`
- Generate a JWT secret

### 3. Configure Environment Variables

Edit `.env` file and add your Google OAuth credentials:

```bash
# JWT Configuration (auto-generated by setup.sh)
JWT_SECRET=your-generated-secret

# Google OAuth Configuration (REQUIRED)
GOOGLE_CLIENT_ID=your-google-client-id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=your-google-client-secret
REDIRECT_URI=http://localhost:8000/api/auth/callback

# Database (pre-configured, change if needed)
DB_USER=jobpulse
DB_PASSWORD=jobpulse_password
DB_NAME=jobpulse_db
```

### 4. Start All Services

```bash
docker-compose up --build
```

Or run in detached mode:

```bash
docker-compose up -d --build
```

### 5. Access the Application

- **Frontend**: http://localhost:3000
- **API Gateway**: http://localhost:8000
- **API Docs**: http://localhost:8000/docs

## Mac-Specific Notes

### ONNX Runtime (Apple Silicon M1/M2/M3)

If you're using Apple Silicon and encounter ONNX Runtime issues, the project uses the standard `onnxruntime` package which works on all platforms. If you need optimized performance, you can use:

```bash
# Inside the Docker container (not required, but optional)
pip install onnxruntime-silicon
```

However, the default `onnxruntime` package works fine on Mac.

### Docker Desktop Settings

1. **Allocate Resources**: 
   - Go to Docker Desktop → Settings → Resources
   - Recommended: 4GB RAM, 2 CPUs minimum

2. **File Sharing**:
   - Ensure the project directory is shared (usually automatic)

### Port Conflicts

If ports are already in use:

- **Port 3000**: Change in `docker-compose.yml` → `frontend` → `ports`
- **Port 8000**: Change in `docker-compose.yml` → `api-gateway` → `ports`
- **Port 5433**: Change in `docker-compose.yml` → `db` → `ports`

### Common Issues

#### Issue: "Permission denied" on setup.sh

**Solution**:
```bash
chmod +x setup.sh
./setup.sh
```

#### Issue: Docker daemon not running

**Solution**: Start Docker Desktop application

#### Issue: Port already in use

**Solution**: 
1. Find the process: `lsof -i :8000`
2. Kill it: `kill -9 <PID>`
3. Or change the port in `docker-compose.yml`

#### Issue: ONNX model not loading

**Solution**: 
- The ONNX model files need to be placed in `services/gmail-connector/models/job_email/onnx/`
- If model files are missing, ONNX inference will be disabled (fallback to rule-based classification)

## Development Workflow

### View Logs

```bash
# All services
docker-compose logs -f

# Specific service
docker-compose logs -f gmail-connector-service
```

### Restart a Service

```bash
docker-compose restart gmail-connector-service
```

### Rebuild After Code Changes

```bash
docker-compose up -d --build gmail-connector-service
```

### Stop All Services

```bash
docker-compose down
```

### Clean Everything (including volumes)

```bash
docker-compose down -v
```

## File Paths

All file paths in the codebase are cross-platform compatible:
- Uses `os.path.join()` for path construction
- Uses Docker volumes for persistent storage
- No hardcoded Windows paths

## Testing

Run tests inside the Docker container:

```bash
docker-compose exec gmail-connector-service python -m pytest tests/
```

## Troubleshooting

### Database Connection Issues

If you can't connect to the database:
1. Check if the database container is running: `docker-compose ps`
2. Check database logs: `docker-compose logs db`
3. Verify `.env` has correct database credentials

### Gmail Sync Not Working

1. Verify Google OAuth credentials in `.env`
2. Check Gmail connector logs: `docker-compose logs gmail-connector-service`
3. Ensure redirect URI matches Google Cloud Console settings

### Frontend Not Loading

1. Check frontend logs: `docker-compose logs frontend`
2. Verify `VITE_API_URL` in `docker-compose.yml` matches your setup
3. Clear browser cache and hard refresh (Cmd+Shift+R)
